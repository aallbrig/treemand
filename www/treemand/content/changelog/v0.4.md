### Added

- tmux-style CLIs whose `--help` lists no subcommands are discovered through `list-commands`, with descriptions taken from the man page; tmux now shows its 90 commands with their flags.
- `--jobs N` sets how many help processes discovery may run at once (`0`, the default, picks 2 x CPUs, between 4 and 16).

### Changed

- Discovery runs each command's help once instead of up to four times, so cold runs of large CLIs such as npm, gh and pip are several times faster.

### Fixed

- Large command groups (for example in docker and gh) no longer come back without flags: the discovery timeout now applies to each command rather than a whole subtree.
- kubectl flags written as `--all-namespaces=false:` with the description on the next line are now parsed.
- A CLI that prints a flood of help output no longer exhausts memory: output is capped at 1 MB per command and what was read is still parsed.
- Short flag lines whose description ends in a word like "output" or "cache" are no longer mistaken for section headers, which had hidden the rest of that section (curl and systemctl regain flags).
