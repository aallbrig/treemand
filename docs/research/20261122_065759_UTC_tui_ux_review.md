# TUI UX review: first run of treemand-tui-ux

This is the first run of the **treemand-tui-ux** skill (#263). It is a product-design review of the interactive TUI, written for the maintainer to triage. Opinions in this report are proposals: none has been filed as an issue. The one deterministic bug the run found was filed separately (#319).

- **Run**: 2026-11-22, treemand built from `db8e687` (main), macOS arm64, git 2.56.
- **Evidence**: `task tui:ux` produced 147 frames: 49 steps across 8 flows, at 80x24, 120x40 and 200x60. Every deterministic check passed (no crash, no panic, no empty frame). Frames live under `.loop/tui-ux/20261122_063644_UTC/`, which is not committed. The paths below are relative to that directory; rerun `task tui:ux` to regenerate them.
- **Method**: every frame was read as text, and the PNGs were read as images, starting at 80x24, against the skill's rubric. Gaps that belong to keymap completeness (#197) or colour contrast (#198) are cited, not re-measured.

## Ranked gaps

The tiers are **dead end** (the task cannot be finished), **misleading** (the screen says something false), **friction** (the task works only with guessing) and **polish**. Within a tier, gaps that a user meets on the first run or in every session come first.

## Deferred to their own skills

- **Help-pane paging moves the tree.** With the help pane focused (its border turns blue, and the status line reads "focus: help"), PgDn left it at `[13%]`. The breadcrumb shows the tree moved instead. This is #311 (tui-keymap conflicts); the frames corroborate it: `80x24/help/07_focus_help_pane`, `08_help_pane_scrolled`.
- **Selection contrast.** The selected row is cyan with a blue name on it (`80x24/assemble/03_pick_command`, `80x24/expand/03_cursor_down_seven`), and flag kinds are told apart by colour (green bool, purple value). Contrast ratios are #198 and #315/#316.
- **Footer truncation** at 80x24 and 200x60 belongs to tui-layout (gap 9 covers which hints are chosen).

## Passes

- **Missing CLI**: `Error: command "..." not found in PATH`, a spelling hint and exit 1, before any TUI is drawn (`*/error_missing/01_opened`).
- **Discovery progress**: first run shows a spinner (`discovering git…`), then `discovering… 22/24` and `discovered 24 commands in 1.8s` (`80x24/open/01_loading`, `120x40/assemble/01_opened`).
- **Value prompt**: the picker names the flag (`Value for --unified:`), shows a placeholder, and states Enter/Esc. Added flags get a ✓ mark, not only a colour (`80x24/assemble/06_value_prompt`, `07_value_typed`).
- **Command preview**: the top line always shows the command being built, coloured by token kind (`80x24/assemble/08_value_added`).
- **Action feedback**: most actions confirm in the status line: `set: git commit`, `added: --unified=3`, `expanded all`, `collapsed all`, `cancelled`, `cleared command`.
- **Escape hatches**: Esc closes the flag picker, the value prompt, the key overlay and the Execute modal without side effects (`*/flags/09_picker_closed`, `*/assemble/11_modal_cancelled`, `*/help/04_overlay_closed`).
- **Conventions**: `?` opens the key overlay, `/` filters, `n` moves to the next match, Tab moves focus, and j/k scroll the overlay.
- **Large terminals**: at 200x60 the help pane fills with the full man page and the rows show whole descriptions (`200x60/expand/04_command_open`).

## Notes on the evidence

- **A 80x24 rendering artefact.** The PNG `80x24/assemble/08_value_added` shows broken pane borders on four tree rows, but the text frame (tmux's own grid) is intact. That makes it a suspected artefact of the vhs renderer, not a TUI bug. It was not counted.
- **Bug found and filed.** The descriptions of `status` and `reset` are mandoc's compatibility warning ("This manpage is not compatible with mandoc(1)…") instead of their NAME line. This is a deterministic discovery bug, filed as #319 (`200x60/expand/04_command_open`).
