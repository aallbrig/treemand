# treemand vision

> Owned by the maintainer. This is the guiding document: when work competes,
> this decides. The dev loop reads it to decide what to build when the backlog
> is empty and **never edits it**; it may propose a change by filing an issue
> labelled `loop:proposed`. Terms are defined in `GLOSSARY.md`.

## What treemand is

treemand turns any CLI into its command tree. It reads the target CLI's own
help (and man pages and completions), builds the tree, and lets people and
programs use it: as static output, in the TUI that assembles a real command line
you can copy or run, and through the agent surface.

**The command tree is the product.** Every view of it is only as good as the
tree. When work competes, it is ranked in this order:

1. **Discovery quality.** Correct trees for more target CLIs and help-text
   families, with fewer stub nodes and misreads.
2. **Honesty.** Every tree is a complete tree, a partial tree or a failed
   discovery, and says which, with the reason.
3. **The TUI.** A killer feature: exploring the tree, reading help beside it,
   and assembling a command, with the tree streaming in as discovery runs.
4. **The agent surface.** Schema-versioned JSON and YAML, and `treemand mcp`.
5. **The website.** treemand.dev and its Try page.
6. **Distribution.** Getting treemand onto every machine and keeping it current.

## Who it is for

- Developers meeting an unfamiliar CLI (kubectl, docker, gh, aws) who want the
  whole shape of it in seconds instead of ten `--help` round trips.
- People who know a CLI can do something but not the exact flag, and want to
  find and assemble it by browsing or searching.
- **Agents.** Agents are a first-class audience, and their use only grows. The
  MCP server run locally (`treemand mcp`) is the main way in, and machine output
  is the other. The agent surface stays as compatible as the CLI's flags.
  Offering it is part of what sets treemand apart.

## Platforms

treemand is a developer tool for every operating system: Linux, macOS and
Windows users all get a working install, an update path and tested behaviour.
(Which machines treemand is *developed* on is a separate matter; see
"Dev host" in the glossary.)

## Principles

1. **Zero setup, any CLI.** Works on target CLIs that never heard of treemand.
   Discovery on messy real-world help output is the core product.
2. **Fast and honest.** Cached trees are instant. Stale, partial or failed
   results are labelled, never silently wrong.
3. **A TUI worth keeping open.** Keyboard-first, mouse-friendly, legible at
   80x24, good at 200 columns, no flicker, no dead ends, no waiting for the
   whole tree before you can start.
4. **Looks professional everywhere.** The website, the demos, the TUI and the
   README should feel like one considered product.
5. **Small, frequent, safe releases.** Main is always releasable. Each release
   ships the few changes merged since the last, is smoke-tested in production
   and can be reverted. Most releases are patches. A written rule picks the
   bump: patch for fixes and improvements to what exists; minor for a new
   command, flag, output format or audience surface; major and `1.0.0` only by
   the maintainer.
6. **Safe to point at anything.** treemand runs a target CLI only with help or
   completion arguments, except when the user explicitly runs an assembled
   command.

## Where it is going (loop: pick from here when idle, in the order above)

- Discovery that handles more help-text families with fewer stub nodes
  (nonstandard help layouts, subcommand aliases, plugin-style CLIs, Windows
  `/?` and PowerShell help).
- Discovery events: discovery reports what it is doing as it happens, so the
  TUI streams the tree in, partial trees say why, and agents see progress.
- Search and navigation that make 500-command CLIs pleasant (fuzzy search,
  jump, bookmarks, recent commands).
- Command assembly: value prompts, enum choices from help text, shell-quoted
  output, one-key copy, and running only after confirmation.
- The agent surface: `treemand mcp`, the JSON Schema, and output formats agents
  and docs use (Markdown, Mermaid, the usage spec).
- A polished website: clear landing page, the Try page as the hero, per-CLI
  gallery of pre-rendered trees, fast and accessible on mobile.
- Distribution: the install one-liners (POSIX shell and PowerShell),
  `treemand update`, and every major package manager on each platform
  (Homebrew, WinGet, Scoop, Chocolatey, AUR, Snap, apt and rpm). A channel is
  turned on when its credentials exist; a missing channel is skipped and never
  blocks a release.

## Out of scope

- Executing discovered commands on the user's behalf without an explicit action.
- Telemetry that leaves the machine.
- Shell history integration.
- Tracking or comparing against competing tools.
- Output formats nobody has asked for (Fig specs, carapace, Graphviz DOT).
- A `1.0.0` declaration. That is the maintainer's call.

## Open questions

- Should changes batch into fewer, larger releases, and by what rule? Until the
  maintainer decides, every user-facing merge ships as soon as it lands.
