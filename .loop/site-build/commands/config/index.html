treemand config

Manage treemand’s optional YAML configuration file without opening it manually.

Commands #

treemand config view               # show merged config + file path
treemand config validate           # check for errors or unknown keys
treemand config validate --strict  # treat warnings as errors
treemand config set <key> <value>  # write a value to the config file
treemand config init               # create a commented default config
treemand config init --force       # overwrite an existing config
treemand config path               # print the config file path
treemand config edit               # open config in $EDITOR

Config file locations #

treemand searches for the config file in this order:

  1. $XDG_CONFIG_HOME/treemand/config.yaml (typically ~/.config/treemand/)
  2. $HOME/.treemand/config.yaml

Precedence #

CLI flags > environment variables (TREEMAND_*) > config file > built-in defaults

Overrides for CLIs treemand misreads #

When treemand reads a CLI’s help wrongly, you can correct the tree yourself without waiting for a release. Put a YAML file named after the CLI in overrides/ beside the config file, for example ~/.config/treemand/overrides/mytool.yaml:

commands:
  # The CLI itself
  "":
    description: My tool does things
    hide_flags: [--debug-internal]
  # A command path below the CLI
  remote add:
    description: Add a remote
    flags:
      # Added, or updates the flag
      - name: --track
        short: -t
        value_type: string
        description: Track one
  # Removed from the tree
  remote prune:
    hide: true
  # Missing: added with its parents
  config set:
    description: Set a value

Each key under commands is a command path without the CLI’s name ("" is the CLI itself). A command can set:

KeyEffect
descriptionReplaces the description
flagsAdds each flag, or updates the fields it sets on an existing flag of that name (short, value_type, description)
hide_flagsRemoves flags by name
hideRemoves the command and everything below it

A command the tree lacks is added, and treemand never runs it to read its help. The override applies to every tree treemand shows for that CLI: text and JSON output, the TUI, --stdin, treemand mcp and treemand doctor. Editing the file takes effect on the next run. An unknown key or invalid YAML is an error that names the file, so a typo never goes unnoticed.

An override is also the most useful thing to attach to a bug report: it shows exactly what treemand got wrong.

Example config #

# ~/.config/treemand/config.yaml
icons: nerd
depth: 5
stub_threshold: 100

colors:
  subcmd: "#5EA4F5"
  flag: "#50FA7B"
  selected: "#00BFFF"

Run treemand config validate after editing to catch typos before they affect behavior.
